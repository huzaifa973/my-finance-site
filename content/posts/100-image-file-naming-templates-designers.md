Every designer has a folder called 'final' containing twelve files named 'final2' through 'final12'. Good file names are a quiet superpower: they make assets findable months later, keep client deliveries professional, and prevent the wrong version from going to print. These one hundred templates cover the naming patterns designers actually use — by client, project, date, location, product, and platform — each with a numbered sequence so versions stay in order. They are built for graphic designers, photographers, and content teams managing growing asset libraries.

## What's inside this resource

The templates follow a few shared rules: lowercase or consistent casing, hyphens or underscores (never spaces), dates in year-month-day order so files sort chronologically, and a three-digit sequence number so version 2 does not sort after version 10. Pick one pattern per project and stick to it — the pattern matters less than the consistency. The pack includes social, print, and web variants, so the same asset can be named correctly for every destination.

## Frequently asked questions

### Should file names contain spaces?

No. Spaces break URLs, scripts, and some older systems. Use hyphens or underscores instead — 'summer-campaign-hero.jpg' works everywhere.

### What date format should I use?

Year-month-day (2026-10-27) sorts chronologically in every file manager. Day-first or month-first formats scramble the order.

### How do I handle final versions?

Never name a file 'final'. Use a version number or date instead — 'final' is always followed by another 'final', and the real final gets lost.
