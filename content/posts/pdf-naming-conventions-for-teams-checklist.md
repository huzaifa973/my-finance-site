Every team has a shared drive full of "Report-FINAL-v2-updated(1).pdf" files, and every team wastes hours figuring out which one is actually current. Bad file names are not a cosmetic problem — they cause people to send the wrong version to clients, duplicate work, and lose documents that search cannot find. This checklist gives your team one naming convention everyone follows: a standard structure for project files, date formats that sort correctly, version numbering that ends the final-final chaos, and the search-friendly habits that make any PDF findable in seconds. Print it, pin it in your team channel, and retire "final_v2_REAL.pdf" forever.

## How to use this checklist

1. Agree on the core structure as a team: date-project-type-version-status. Write it down where everyone can see it.
2. Rename your current active files first — the mess in /archive can wait, but today's working files should follow the convention immediately.
3. Create the folder README (template in the download) that documents the convention for new team members.
4. Set a five-minute monthly audit: one person scans for "final", "copy of", and duplicate names, and renames offenders.
5. Add the naming rule to your onboarding checklist so new hires learn it on day one.

The convention only works if everyone follows it, so keep the rules short and the examples visible. Teams that post the cheat sheet in their shared drive adopt it within a week; teams that bury it in a wiki never do.

## Frequently asked questions

**What if a client sends us badly named files?**
Rename your working copy to your convention and keep the original filename noted in the file's metadata or a README. Never send a badly named file back out — rename it before it leaves your team.

**How do we handle filenames that are too long?**
Cap filenames at about 60 characters. Drop the least important element first — usually the date (it's in the file metadata) or the project code (it's in the folder name). Keep the document type and version, which are the parts people search for.

**Does this apply to non-PDF files too?**
Yes. The same structure works for spreadsheets, images, and documents. Only the extension changes — the discipline is identical.
