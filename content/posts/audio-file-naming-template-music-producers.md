Every producer knows the pain of opening a folder full of “final_FINAL_v3_NEW.wav” files and having no idea which one is actually final. A naming system fixes that — not with discipline, but with a pattern so obvious that breaking it feels wrong. This template gives you one system for stems, mixes, masters, and samples, with twenty example filenames you can copy as your own convention.

## What's inside this resource

The system is: Artist — Project — Element — Version — Date, always in that order, always with the same separators. Version numbers beat words like “final” (final is a lie the moment you reopen the file), and dates beat memory. The examples below show the pattern applied to real session files.

## How to use this resource

1. Adopt the pattern for one project first, then roll it out to older sessions as you open them.
2. Never use “final” in a filename — use version numbers and let the highest number win.
3. Keep one folder per project with subfolders for stems, mixes, and masters.
4. Rename on export, not later — a file named at export never gets lost.
5. Share the convention with collaborators before the first file exchange, not after.

A resource is only useful when it gets used — pick one item today, use it as written, and adapt it from experience rather than from theory.

## Frequently asked questions

**Should filenames include the BPM and key?**

For samples and loops, yes — BPM and key are how you find them later. For mixes and masters, version and date matter more.

**What separator should I use?**

Hyphens or underscores, consistently. Avoid spaces: they break command-line tools and some upload systems.

**How do I fix an old messy library?**

Do not rename everything at once. Apply the system to new files, and rename old files when you actually open them.
